## 1. Как это устроено

```
frontend-kit/  (шаблон, этот репозиторий)          my-site/  (проект)
├── kit/        ── копия при создании ──────────▶  ├── kit/        своя копия
├── starters/vanilla ── копия в корень ─────────▶  ├── index.html, src/, …
├── docs/, test/, конфиги ── копия ─────────────▶  ├── docs/, test/, конфиги
└── package.json ── версии пакетов ─────────────▶  └── package.json (только нужное)

        npm run create -- --update ../my-site  ──▶  обновляет kit/ (и пакеты, если не хватает)
```

**Кит копируется, а не ставится как npm-пакет.** На фрилансе проекты живут годами и отдельно:
пакет пришлось бы публиковать и версионировать, а правка под один проект ломала бы другие.
Копию можно менять под проект, а обновить из шаблона — одной командой. Проект после создания
**полностью самостоятельный**: его можно отдать заказчику, шаблон ему не нужен.

## 2. Создать проект: `npm run create`

Команды запускаются **из папки шаблона**:

```bash
cd frontend-kit
npm install                                       # один раз, зависимости самого шаблона
npm run create -- ../my-site --stack vanilla      # вёрстка: HTML-компоненты + JS-модули
npm run create -- ../my-app --stack react         # React-приложение (JS)
npm run create -- ../my-app --stack react-ts      # React + TypeScript
npm run create -- ../my-site --stack astro        # Astro: статический сайт, языки, SEO
npm run create                                    # спросит папку и стек сам
```

`--` после `npm run create` обязательно: всё после него передаётся скрипту, а не npm.

| Флаг                                      | Что делает                                           |
| ----------------------------------------- | ---------------------------------------------------- |
| `--stack vanilla\|react\|react-ts\|astro` | стек (без флага — спросит)                           |
| `--install`                               | сразу `npm install` в новом проекте                  |
| `--git`                                   | `git init` и первый коммит                           |
| `--name my-site`                          | имя в `package.json` (по умолчанию — из имени папки) |

Обычно так:

```bash
npm run create -- ../shop-landing --stack vanilla --install --git
cd ../shop-landing
npm run dev
```

**Какой стек выбрать:**

| Проект                                                                   | Стек                                                                                                   |
| ------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------ |
| Вёрстка под CMS (Битрикс, WordPress, Django), лендинг, промо             | `vanilla`                                                                                              |
| Сайт с SEO и скоростью, несколько языков, портфолио, блог, сайт компании | `astro`                                                                                                |
| Личный кабинет, дашборд, много состояния на клиенте                      | `react-ts` (или `react` без TS)                                                                        |
| Next.js                                                                  | создайте Next-проект как обычно и перенесите `kit/` — [frameworks.md](frameworks.md#nextjs-app-router) |

Папка проекта не должна существовать или должна быть пустой. Внутри шаблона создавать нельзя.

## 3. Что получается

```
my-site/
├── index.html, ui-kit.html, …     страницы (vanilla) / src/pages (astro, react)
├── src/                           код проекта: компоненты, модули, плагины, стили, данные
├── kit/                           копия кита (без kit/react, если стек не React)
├── docs/                          эта документация
├── test/                          помощники для тестов
├── mocks/                         фейковый API для dev
├── package.json                   ТОЛЬКО пакеты этого стека, версии — из шаблона
├── vite.config.js / astro.config  пути к kit уже исправлены (../../kit → ./kit)
├── eslint, stylelint, prettier, vitest, tsconfig, .editorconfig, .vscode
└── README.md                      README проекта: команды и где что лежит
```

Скрипты в `package.json` проекта:

| Команда                              | Что делает                                                    |
| ------------------------------------ | ------------------------------------------------------------- |
| `npm run dev`                        | разработка с перезагрузкой                                    |
| `npm run build`                      | готовый сайт в `dist/`                                        |
| `npm run preview`                    | посмотреть собранный сайт                                     |
| `npm test` / `npm run test:watch`    | тесты                                                         |
| `npm run lint` / `npm run fix`       | проверка / автоисправление стиля кода                         |
| `npm run check`                      | всё сразу: линтеры, типы, тесты, сборка — перед каждой сдачей |
| `npm run new -- component card --js` | (vanilla) заготовка компонента, модуля, плагина или страницы  |

Сразу после создания: поменять цвета и шрифты в `src/styles/_abstracts.scss`, название и
контакты — в `src/data/site.json` (vanilla), заменить `public/favicon.svg`. Дальше —
[getting-started.md](getting-started.md).

## 4. Обновить кит в проекте: `--update`

Шаблон развивается: исправляются баги, появляются модули. Перенести это в проект:

```bash
cd my-site && git add -A && git commit -m "до обновления кита"   # 1. сохранить текущее
cd ../frontend-kit && git pull                                     # 2. свежий шаблон
npm run create -- --update ../my-site                              # 3. обновить kit/
cd ../my-site && npm install                                       # 4. если добавились пакеты
git diff                                                           # 5. посмотреть, что изменилось
npm run check                                                      # 6. всё ли работает
git add -A && git commit -m "Кит обновлён"
```

**Что делает `--update`:**

| Что                                                     | Обновляется?                                                                                                |
| ------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `kit/`                                                  | ✅ перезаписывается целиком (новые файлы добавляются, старые обновляются)                                   |
| `test/` (помощники тестов)                              | ✅                                                                                                          |
| `package.json`                                          | ✅ только **добавляет** пакеты, которых нет (новому модулю нужна библиотека). Версии существующих не меняет |
| Конфиги: eslint, stylelint, prettier, vitest, `.vscode` | только с флагом `--configs`                                                                                 |
| `src/`, страницы, стили, данные проекта                 | ❌ никогда                                                                                                  |
| `.gitignore`, `README.md`, `vite.config.js` проекта     | ❌ никогда                                                                                                  |

```bash
npm run create -- --update ../my-site --configs   # и общие настройки тоже
```

После `--configs` посмотрите `git diff`: если вы меняли настройки линтера под проект, верните
свои правки.

**Стек определяется сам** по `package.json` проекта: есть `react` — React, есть `astro` —
Astro, иначе vanilla.

**Что почитать после обновления:** `git log` шаблона — в сообщениях коммитов написано, что
изменилось и зачем. Если поменялось поведение модуля — это будет в
[troubleshooting.md](troubleshooting.md) и в комментарии в начале файла модуля.

## 5. Если кит в проекте правили

`--update` перезаписывает `kit/` — правки в нём пропадут. Поэтому:

1. **Не правьте кит — переопределяйте.** Нужен аккордеон «чуть по-другому»: создайте
   `src/modules/accordion/index.js` в проекте — одноимённый модуль проекта **заменяет** модуль
   кита (реестр в `src/main.js`: модули проекта идут после модулей кита). Стили — в
   `src/styles/`, они подключаются после кита и перебивают его без `!important`.
2. **Правка нужна всем проектам** (нашли баг в ките) — исправьте в **шаблоне**, закоммитьте и
   обновите проекты через `--update`.
3. **Всё-таки правили `kit/` в проекте** — перед `--update` закоммитьте проект. После
   обновления `git diff kit/` покажет, что ваша правка пропала, — перенесите её в шаблон или в
   переопределение (п. 1) и закоммитьте.

## 6. Обновить библиотеки (npm-пакеты)

Версии всех пакетов живут **в `package.json` шаблона** — один источник правды. Новый проект
получает их оттуда.

### В шаблоне

```bash
cd frontend-kit
npm outdated                 # что устарело: Current — стоит, Wanted — в пределах ^, Latest — новейшая
npm update                   # обновить в пределах ^ (без смены мажорной версии) — обычно безопасно
npm run check                # линтеры, типы, все тесты, сборка всех 4 стартеров
```

**Мажорная версия** (Latest отличается первой цифрой: `swiper 14 → 15`) — по одному пакету:

```bash
npm install swiper@latest
npm run check                # упало — читать changelog пакета (ссылка в libraries.md)
npm run dev                  # посмотреть страницы ui-kit.html и effects.html глазами
git commit -am "swiper 15"
```

Не обновляйте все мажорные версии разом: если что-то сломалось, непонятно, из-за чего.

### В проекте

`--update` версии не меняет (проект мог обновить пакет сам или зависеть от старой версии).
Обновить в проекте:

```bash
cd my-site
npm outdated
npm update                          # в пределах ^
npm install gsap@^3.16.0            # конкретный пакет до версии из шаблона
npm run check
```

Версия, проверенная в шаблоне, — в `package.json` шаблона. Ставьте её, а не просто
`@latest`: она прошла все тесты кита.

### Node.js

Нужен Node из `.nvmrc` (`engines` в `package.json`). С nvm: `nvm use` в папке проекта.

## 7. Шаблон на другом компьютере

Шаблон — обычный git-репозиторий:

```bash
git clone https://github.com/dmitriy9427/frontend-kit.git
cd frontend-kit
npm install
npm run dev                  # демо: http://localhost:5173
npm run create -- ../new-site --stack vanilla --install --git
```

Изменили шаблон — `npm run check`, коммит, `git push`. Демо шаблона на GitHub Pages
пересобирается само (`.github/workflows/pages.yml`).

## 8. Шпаргалка

| Хочу                         | Команда (из папки шаблона, если не сказано иное)                                |
| ---------------------------- | ------------------------------------------------------------------------------- |
| Новый проект                 | `npm run create -- ../site --stack vanilla --install --git`                     |
| Обновить кит в проекте       | `npm run create -- --update ../site` → в проекте `npm install`, `npm run check` |
| …и конфиги линтеров          | `npm run create -- --update ../site --configs`                                  |
| Посмотреть устаревшие пакеты | `npm outdated` (в шаблоне или проекте)                                          |
| Обновить пакеты в пределах ^ | `npm update` → `npm run check`                                                  |
| Новый компонент (в проекте)  | `npm run new -- component card --js`                                            |
| Справка по create            | `npm run create -- --help`                                                      |

# 06. Стили — с нуля

## Зачем SCSS, если есть CSS

В CSS уже есть переменные (`var(--color-accent)`). SCSS нужен для того, что происходит **до**
браузера, при сборке:

| Задача                              | Чистый CSS                                              | SCSS кита                                         |
| ----------------------------------- | ------------------------------------------------------- | ------------------------------------------------- |
| Отступ «4 шага по 4px» в rem        | `padding: 1rem` — посчитать руками                      | `padding: space(4)`                               |
| «От планшета и шире»                | `@media (min-width: 768px)` — помнить число в 40 местах | `@include up('md')`                               |
| Опечатка в имени цвета              | `var(--color-acent)` — молча прозрачный текст           | `color('acent')` — **сборка падает** с подсказкой |
| Плавный размер шрифта от 28 до 56px | формула `clamp()` руками                                | `fluid(28px, 56px)`                               |
| Hover без «залипания» на телефоне   | помнить медиазапрос                                     | `@include hover { … }`                            |

SCSS компилируется в обычный CSS — в браузер уходит только результат.

## Самый маленький пример

```scss
// src/components/team-card/team-card.scss
@use 'abstracts' as *; // подключить функции и миксины кита

.team-card {
  padding: space(4); // → 1rem
  border-radius: radius('md'); // → var(--radius-md)
  background: color('surface'); // → var(--color-surface)

  @include up('md') {
    // → @media (min-width: 768px)
    padding: space(8); // → 2rem
  }

  @include hover {
    // → @media (hover: hover) and (pointer: fine) { &:hover
    box-shadow: var(--shadow-md);
  }
}
```

Первая строка `@use 'abstracts' as *;` обязательна в каждом файле: без неё SCSS не знает про
`space()` и `up()`. CSS она не выводит — дублирования не будет, сколько файлов её ни подключай.

## Три слоя стилей

```
kit/scss/
├── _config.scss     НАСТРОЙКИ: цвета, брейкпоинты, шрифты — всё с !default
├── abstracts/       ИНСТРУМЕНТЫ: функции и миксины — CSS не выводят
├── base/            ОСНОВА: сброс, типографика, CSS-переменные на :root, утилиты
└── components/      ГОТОВЫЕ БЛОКИ: кнопка, поля, модалка, аккордеон…
```

И в проекте:

```
src/styles/
├── _abstracts.scss  ← ваши настройки поверх кита
├── main.scss        ← подключает всё по порядку
├── _layout.scss     ← общая раскладка проекта
└── sections/        ← стили секций страниц
```

`main.scss` стартера:

```scss
@use 'abstracts'; // 1. настройки проекта (они же применяются к киту)
@use 'kit/scss'; // 2. CSS кита: сброс, база, компоненты
@use 'layout'; // 3. стили проекта — после кита, поэтому важнее
@use 'sections/hero';
```

**Порядок важен.** Стили проекта идут после кита — при равной специфичности побеждает последнее
правило, и ваш `.btn` перекроет китовый без `!important`.

## Настройки: как поменять цвета, не трогая кит

В ките все настройки объявлены с `!default`:

```scss
// kit/scss/_config.scss
$container-max: 1280px !default;
$colors: () !default;
$colors-defaults: (
  'bg': #fff,
  'accent': #3b5bff,
  'text': #14161a,
  …,
);
```

`!default` значит «это значение, **если никто не задал другое**». А задать другое можно при
подключении — через `with`:

```scss
// src/styles/_abstracts.scss проекта
@forward 'kit/scss/abstracts' with (
  $colors: (
    'accent': #ff5a1f,
    'bg': #fffaf5,
  ),
  $container-max: 1200px
);
```

Тонкость с картами: вы передали **только два цвета**, а в ките их одиннадцать. Не пропадут ли
остальные? Нет — в конце `_config.scss` карты **сливаются**:

```scss
$colors: map.merge($colors-defaults, $colors);
// = все цвета по умолчанию, поверх них — ваши два
```

Поэтому указывайте только то, что меняете.

> **Почему не править `kit/scss/_config.scss` напрямую?** Кит обновляется командой `--update` и
> перезапишет правки. Настройки проекта живут в проекте.

## Функции: считают значения

### `space(n)` — шкала отступов

```scss
gap: space(2); // 8px  → 0.5rem
gap: space(4); // 16px → 1rem
gap: space(6); // 24px → 1.5rem
```

Отступы кратны 4. Дизайнеры обычно так и рисуют, а вы перестаёте выбирать между 15, 16 и 17
пикселями.

### `rem(px)` — пиксели в rem

```scss
font-size: rem(18px); // 1.125rem
```

Зачем rem: человек увеличил шрифт в настройках браузера (плохое зрение) — вёрстка в rem
масштабируется вместе с ним, а в px нет.

> Не ставьте `html { font-size: 62.5% }` («чтобы 1rem = 10px»). Это ломает пользовательский
> размер шрифта. Для удобства и есть `rem()`.

### `fluid(min, max)` — плавный размер без медиазапросов

```scss
h1 {
  font-size: fluid(28px, 56px);
}
```

На экране 360px заголовок 28px, на 1440px — 56px, между ними растёт плавно. Функция считает
`clamp()`:

```css
h1 {
  font-size: clamp(1.75rem, 1.1667rem + 2.59vw, 3.5rem);
}
```

Математика — прямая через две точки: (360px → 28px) и (1440px → 56px).

- наклон: `(56 − 28) / (1440 − 360) = 0.0259` — на каждый пиксель ширины экрана шрифт растёт
  на 0.0259px. В единицах экрана это `2.59vw` (1vw — сотая часть ширины);
- смещение: `28 − 0.0259 × 360 ≈ 18.67px = 1.1667rem` — где прямая пересекла бы ноль ширины.

`clamp` не даёт выйти за 28 и 56.

### `color(name)`, `radius(name)`, `z(layer)` — имена с проверкой

```scss
color: color('accent'); // var(--color-accent)
color: color('acent'); // ✗ сборка упадёт: «Нет цвета «acent». Есть: bg, surface, text, …»
z-index: z('header'); // 200
z-index: z('modal'); // ✗ «Нет слоя «modal». Есть: below, base, sticky, header, …, dialog»
```

**Слои z-index** — отдельная история. В любом проекте через год встречается `z-index: 99999`,
потому что «что-то перекрывало». В ките все слои в одном списке:

```
below -1 → base 1 → sticky 100 → header 200 → popover 250 → menu 300
→ dialog 400 → cookie 450 → toast 500 → tooltip 600
```

Видно, что над чем. Нужен новый слой — добавьте его в `$z-layers` проекта, а не пишите число.

## Миксины: вставляют куски CSS

### Брейкпоинты: mobile-first

```scss
.grid {
  display: grid;
  gap: space(4); // телефон: одна колонка

  @include up('md') {
    // от 768px
    grid-template-columns: 1fr 1fr;
  }
  @include up('lg') {
    // от 1024px
    grid-template-columns: repeat(3, 1fr);
  }
}
```

**Mobile-first** — сначала стили для телефона, потом «от такой-то ширины и шире». Так CSS
короче: телефон получает базовые правила, большие экраны — добавки.

Брейкпоинты: `sm` 576, `md` 768, `lg` 1024, `xl` 1280, `xxl` 1440.

Есть и `down('md')` — «уже 768px». Внутри интересная деталь:

```scss
@mixin down($name) {
  @media (max-width: bp($name) - 0.02px) {
    @content;
  }
}
```

Почему `- 0.02px`, а не `- 1px`? На Windows с масштабом 125% ширина окна бывает **дробной**:
767.5px. При `max-width: 767px` такая ширина не попадает ни в `down('md')`, ни в `up('md')` — и
вёрстка ломается ровно на одном размере окна. 0.02px закрывает эту щель.

### `hover` — без «залипания» на телефоне

```scss
.btn {
  @include hover {
    background: color('accent');
  }
}
```

На тач-экране `:hover` срабатывает от тапа и **остаётся**, пока не тапнешь в другое место:
кнопка «залипает» подсвеченной. Миксин оборачивает hover в `@media (hover: hover) and
(pointer: fine)` — только для мыши. `hocus` — hover плюс фокус с клавиатуры.

### `motion` — анимации только для тех, кто не против

```scss
.card {
  @include motion {
    transition: transform 0.3s;
  }
}
```

В настройках ОС есть «Уменьшить движение» — у людей с вестибулярными нарушениями от анимаций
кружится голова. Миксин включает анимацию, только если такой настройки нет.

## CSS-переменные: мост между SCSS и браузером

SCSS-переменные исчезают после сборки. Но некоторые значения нужны **в браузере**: тёмная тема
меняет цвета на лету, а JS хочет знать брейкпоинты. Поэтому `base/_root.scss` выводит настройки
в CSS-переменные:

```scss
:root {
  @each $name, $value in $colors { --color-#{$name}: #{$value}; }
  @each $name, $value in $breakpoints { --bp-#{$name}: #{$value}; }
  …
}
```

Результат:

```css
:root {
  --color-bg: #fff;
  --color-accent: #3b5bff;
  --bp-md: 768px;
  …
}
```

### Тёмная тема в 10 строк

```scss
:root[data-theme='dark'] {
  // 1. выбрал тёмную вручную
  @include -color-vars($colors-dark);
  color-scheme: dark;
}

@media (prefers-color-scheme: dark) {
  // 2. тёмная в системе…
  :root:not([data-theme='light']) {
    //    …и не выбрал светлую вручную
    @include -color-vars($colors-dark);
    color-scheme: dark;
  }
}
```

Три состояния без единой строки JS:

| В системе | Человек выбрал | `data-theme` | Тема                                |
| --------- | -------------- | ------------ | ----------------------------------- |
| светлая   | ничего         | нет          | светлая                             |
| тёмная    | ничего         | нет          | **тёмная** (правило 2)              |
| тёмная    | «светлая»      | `light`      | светлая (`:not` исключил правило 2) |
| светлая   | «тёмная»       | `dark`       | тёмная (правило 1)                  |

Модуль `theme-switch` только ставит `data-theme` и запоминает выбор. `color-scheme: dark` —
чтобы скроллбары, поля ввода и календарь браузера тоже стали тёмными.

Почему везде `color('accent')` → `var(--color-accent)`, а не сам цвет `#3b5bff`? Именно поэтому:
переменная **меняется** при смене темы, а вписанный цвет — нет.

### Один источник правды для брейкпоинтов

JS тоже нужно знать, где «планшет»: например, меню-бургер работает только до `lg`. Вместо
того чтобы продублировать `1024` в JS, кит читает CSS-переменную:

```js
export function getBreakpoints() {
  const style = getComputedStyle(document.documentElement)
  // --bp-lg: 1024px → { lg: 1024, … }
}
```

Поменяли брейкпоинт в `_abstracts.scss` — поменялся и в CSS, и в JS.

## Ошибки

> **«Undefined function space»** — в файле нет `@use 'abstracts' as *;`.
>
> **«This module was already loaded, so it can't be configured using with»** — `abstracts`
> подключили где-то **до** `main.scss` с другой конфигурацией. Настройки задаются ровно в одном
> месте — `src/styles/_abstracts.scss`.
>
> **Стиль проекта не перекрывает кит** — специфичность кита выше (`.form .btn` против `.btn`) или
> файл подключён до `kit/scss`. Проверьте порядок в `main.scss`.
>
> **`z-index: 9999` — и всё равно под шапкой** — элемент внутри родителя с `transform` или
> `opacity < 1`: такой родитель создаёт свой «контекст наложения», и z-index работает только
> внутри него. Слои кита не помогут — уберите transform у родителя (глава 07: `clearProps`).
>
> **Hover не работает в тесте на тач-эмуляции DevTools** — так и задумано, миксин `hover` для мыши.

<details>
<summary>Ответы</summary>

2. `5 × 4px = 20px = 1.25rem`.
3. ```scss
   .cards {
     display: grid;
     gap: space(6);
     @include up('md') {
       grid-template-columns: 1fr 1fr;
     }
   }
   ```
4. Страница стала тёмной (правило `:root[data-theme='dark']`). При `light` — светлой даже с
   тёмной системой: `:root:not([data-theme='light'])` перестал совпадать.

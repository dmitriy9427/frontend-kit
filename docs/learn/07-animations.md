# 07. Анимации — с нуля

## Зачем GSAP, если есть CSS-анимации

CSS-переходы хороши для простого: кнопка меняет цвет, панель раскрывается. Но заказчик хочет:

- карточки появляются **волной**, когда до них докрутили;
- секция **закрепляется**, а лента внутри едет вбок, пока листаете вниз;
- число «досчитывает» от 0 до 1 500;
- всё это **точно привязано к скроллу** и не дёргается на телефоне.

Для этого кит использует **GSAP** (библиотека анимаций) и его плагин **ScrollTrigger**
(«запусти, когда блок доехал до места»). С версии 3.13 все плагины GSAP бесплатны, в том числе
для коммерции.

## Самый маленький пример: GSAP

```js
import { gsap } from 'kit/js/core/gsap.js'

gsap.to('.box', { x: 200, duration: 1 }) // уехать вправо на 200px за секунду
gsap.from('.box', { opacity: 0, y: 40 }) // появиться ИЗ прозрачного и снизу
gsap.set('.box', { opacity: 0 }) // мгновенно, без анимации
```

| Метод               | Значит                                |
| ------------------- | ------------------------------------- |
| `to(цель, { … })`   | из текущего состояния **в** указанное |
| `from(цель, { … })` | **из** указанного в текущее           |
| `set(цель, { … })`  | поставить сразу                       |

То, что вернул `gsap.to`, называется **твин** (tween — «промежуточное»). Его можно остановить:
`tween.kill()`.

## Самый маленький пример: ScrollTrigger

```js
import { gsap, ScrollTrigger } from 'kit/js/core/gsap.js'

gsap.from('.title', {
  opacity: 0,
  y: 40,
  scrollTrigger: {
    trigger: '.title', // за каким элементом следить
    start: 'top 85%', // когда ВЕРХ элемента дошёл до 85% высоты экрана
  },
})
```

`start: 'top 85%'` читается как «**верх элемента** совпал с **линией на 85% экрана** (сверху)».
То есть элемент только-только показался внизу.

```
┌──────────── экран ────────────┐  0%
│                               │
│                               │
│                               │
│ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ │  85%  ← линия start
│ ┌─────── .title ──────┐       │
└─┴─────────────────────┴───────┘  100%
  ↑ верх элемента дошёл до линии — анимация пошла
```

Ещё два слова, которые встречаются в модулях кита:

- **`scrub`** — анимация не проигрывается сама, а **следует за скроллом**: прокрутили на
  половину пути — анимация на половине. Крутите назад — идёт назад.
- **`pin`** — элемент **закреплён** на экране, пока идёт анимация. Страница как будто остановилась,
  а скролл двигает что-то внутри.

## Импорт — только из одного места

```js
import { gsap, ScrollTrigger } from 'kit/js/core/gsap.js' // ✓ в модулях кита
import { gsap, SplitText } from '@/lib/gsap.js' // ✓ в коде проекта
import { gsap } from 'gsap' // ✗ не надо
```

[kit/js/core/gsap.js](../../kit/js/core/gsap.js) делает две вещи:

```js
gsap.registerPlugin(ScrollTrigger)

// На телефоне при прокрутке прячется/появляется адресная строка — высота окна
// меняется. По умолчанию ScrollTrigger на это всё пересчитывает → «прыжки».
ScrollTrigger.config({ ignoreMobileResize: true })
```

Забытый `registerPlugin` — частая ошибка: «SplitText is not defined» или «анимация молча не
работает». Импорт из одного файла гарантирует, что плагин зарегистрирован.

В проекте `src/lib/gsap.js` — то же самое для плагинов проекта плюс общий характер анимаций:

```js
gsap.defaults({ ease: 'power3.out', duration: 0.8 })
```

## Как это сделано в ките: модуль `reveal`

Самый используемый модуль — появление при прокрутке:

```html
<section data-module="reveal">
  <h2 data-reveal>Заголовок</h2>
  <!-- снизу вверх (по умолчанию) -->
  <p data-reveal="fade">Текст</p>
  <!-- просто проявляется -->
  <li data-reveal="up" data-reveal-delay="0.1">…</li>
</section>
```

Модуль ставится на контейнер (хоть на весь `<main>`) и анимирует всех потомков с `data-reveal`.
Внутри [reveal/index.js](../../kit/js/modules/reveal/index.js) три интересные задачи.

### Задача 1: не «мигнуть»

Наивно: CSS ничего не прячет, JS запускается и делает `gsap.set(el, { opacity: 0 })`. Между
загрузкой страницы и запуском JS проходит 100–300 мс — человек **видит** заголовок, потом он
исчезает и плавно появляется снова. Это и есть «мигание».

Наивно-2: CSS прячет `[data-reveal] { opacity: 0 }`. Тогда если JS не загрузился (ошибка, медленная
сеть, блокировщик) — страница **пустая навсегда**.

Решение кита — в три шага:

```scss
// kit/scss/base/_a11y.scss
.js [data-reveal]:not(.is-revealed) {
  opacity: 0;
  animation: kit-reveal-fallback 0s 3s forwards; // страховка: через 3 с показать всё
}
```

1. CSS прячет, **только если на `<html>` есть класс `js`**. Его ставит крошечный встроенный
   скрипт в `<head>` (компонент `site-head`) — ещё до того, как браузер нарисует первый кадр.
   Нет JS — нет класса — всё видно.
2. Модуль в момент запуска в одном и том же кадре ставит `is-revealed` (CSS перестаёт прятать)
   и `gsap.set(el, { opacity: 0, y: 40 })` (теперь прячет GSAP). Браузер не успевает нарисовать
   промежуточный кадр.
3. ScrollTrigger проигрывает появление.

### Задача 2: что уже на экране — показать сразу

```js
const visible = new Set(targets.filter(inViewport))   // мерить ДО gsap.set (он сдвигает y)
…
if (visible.size) show([...visible])
```

Линия `start` — 85% экрана. А что, если элемент виден, но ниже этой линии? Например, цифры
внизу первого экрана. Они висели бы невидимыми, пока человек не прокрутит. Поэтому всё, что на
экране при загрузке, показывается сразу, без ожидания скролла.

### Задача 3: волна и уборка за собой

```js
ScrollTrigger.batch(rest, { start: options.start, once: true, onEnter: show })
```

`batch` собирает элементы, которые вошли в экран **одновременно** (ряд из трёх карточек), и
отдаёт их одной пачкой — `show` анимирует их с `stagger: 0.08`: каждая следующая на 80 мс позже.
Получается волна.

```js
gsap.to(batch, {
  opacity: 1,
  x: 0,
  y: 0,
  scale: 1,
  stagger: options.stagger,
  clearProps: 'transform,clipPath', // ← важная строка
})
```

`clearProps` после анимации **убирает** inline-стиль `transform`. Зачем? Элемент с `transform`
(даже `translate(0, 0)`) становится «контейнером» для `position: fixed` внутри себя. Кнопка
«Наверх» с `position: fixed` внутри такого блока перестаёт быть фиксированной к окну и
уезжает вместе с блоком. Очень трудно найти, если не знать.

## Уважать «меньше движения»

Каждый модуль кита получает `ctx.reduced` — включена ли в ОС настройка «Уменьшить движение»:

```js
if (ctx.reduced) {
  targets.forEach((el) => el.classList.add('is-revealed')) // просто показать всё
  return
}
```

Это не вежливость, а доступность: у людей с вестибулярными нарушениями параллакс и
скролл-анимации вызывают головокружение и тошноту. В CSS то же самое делает миксин `motion`
(глава 06).

Проверить у себя: DevTools → ⋮ → More tools → Rendering → Emulate CSS media feature
`prefers-reduced-motion: reduce`, затем перезагрузить страницу.

## Почему «анимация срабатывает не там»

Самая частая жалоба на ScrollTrigger. Три причины и как кит их закрывает.

### Причина 1: высота страницы поменялась после расчёта

ScrollTrigger при запуске **запоминает**, на каком пикселе скролла начинается каждая анимация.
Потом догружается картинка выше — всё сдвигается на 400px вниз, а запомненные числа старые.
Анимация срабатывает раньше, чем блок доехал.

Кит следит за высотой `body` и пересчитывает:

```js
// kit/js/core/app.js
const refresh = debounce(() => { ScrollTrigger.sort(); ScrollTrigger.refresh() }, 200)
new ResizeObserver(() => {
  if (document.body.scrollHeight !== lastHeight) { lastHeight = …; refresh() }
}).observe(document.body)
document.fonts?.ready.then(() => refresh())        // догрузились шрифты — строки стали другой длины
```

`debounce(…, 200)` — «выполнить через 200 мс после **последнего** вызова». Галерея из 30 картинок
вызовет пересчёт один раз, а не 30.

### Причина 2: порядок создания

Секция A выше по странице **закреплена** (`pin`) на 1000px скролла. Секция B ниже. Позиция B
должна учитывать эти 1000px. ScrollTrigger считает позиции **в порядке создания** — и если B
создан раньше A (модули ленивые и грузятся в случайном порядке!), B про 1000px не знает.

```js
// после запуска всех модулей
ScrollTrigger.sort() // упорядочить по положению на странице
ScrollTrigger.refresh() // пересчитать
```

### Причина 3: телефон и адресная строка

`ignoreMobileResize: true` в `kit/js/core/gsap.js` — уже разобрали выше.

## Плавный скролл: Lenis

На десктопе кит включает **Lenis** — колесо мыши прокручивает страницу плавно, с инерцией.
Выключается сам:

- на **тач-устройствах** — родная инерция пальца лучше любой эмуляции, а на iOS Lenis ломает
  «резинку» и жест «назад»;
- при **«меньше движения»**.

Почему Lenis, а не ScrollSmoother из GSAP: Lenis двигает **настоящий** скролл окна. Работают
`position: sticky`, якоря, поиск по странице Ctrl+F. ScrollSmoother требует обёртку на всю
страницу и ломает эти вещи.

Две тонкости, о которых модули знают:

1. **Lenis и GSAP — в одном кадре.** Lenis обновляется от `gsap.ticker`, иначе анимации на
   скролле дрожат на полкадра.
2. **Вложенная прокрутка.** Без настройки Lenis перехватывает колесо **везде**: внутри
   модалки крутится страница под ней. Кит отдаёт колесо браузеру, если блок под курсором сам
   умеет прокручиваться, а для `dialog`, меню, выпадающих списков — всегда. Свой блок —
   `data-lenis-prevent`.

## Модуль с закреплением: `hscroll`

Горизонтальная лента — листаете вниз, лента едет вбок. Главное в
[hscroll/index.js](../../kit/js/modules/hscroll/index.js):

```js
const distance = () => Math.max(0, track.scrollWidth - window.innerWidth) // «лишняя» ширина

const move = gsap.to(track, {
  x: () => -distance(), // уехать влево на «лишнюю» ширину
  ease: 'none', // ← обязательно
  scrollTrigger: {
    trigger: pin,
    pin, // закреплённый блок стоит на месте
    start: 'top top',
    end: () => `+=${distance()}`, // столько px скролла, сколько ехать ленте
    scrub: 0.8, // лента следует за скроллом с небольшой мягкостью
    invalidateOnRefresh: true, // при ресайзе посчитать заново
  },
})
```

Весь этот код обёрнут в `gsap.matchMedia()`: с `data-hscroll-min="md"` эффект живёт только на
широких экранах, а при повороте телефона GSAP сам всё убирает и создаёт заново.

| Строка                             | Почему так                                                                                                                                               |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `x: () => …` (функция, а не число) | окно поменяли — длина пути другая; функция посчитает заново при `refresh`                                                                                |
| `ease: 'none'`                     | лента должна ехать **линейно** со скроллом. С `power3` начало было бы медленным, середина быстрой — и «внутренние» анимации карточек сработали бы не там |
| `end: +=ширина`                    | на сколько пикселей скролла растянуть анимацию. Равно пути ленты — тогда скорость ленты = скорости скролла, и кажется, что вы листаете её саму           |

Карточки внутри ленты тоже анимируются — но обычный ScrollTrigger следит за **вертикалью**, а
карточки едут вбок. Для этого `containerAnimation: move`: «считай положение карточки внутри
горизонтальной анимации». Тогда `start: 'left 80%'` значит «левый край карточки дошёл до 80%
ширины окна».

## Уборка анимаций

Каждый модуль с анимациями в `destroy` делает три вещи:

```js
destroy() {
  triggers.forEach((t) => t.kill())          // 1. снять наблюдение за скроллом
  gsap.killTweensOf(targets)                 // 2. остановить идущие анимации
  gsap.set(targets, { clearProps: 'all' })   // 3. вернуть элементы как было
}
```

Без пункта 3 элементы так и останутся с `opacity: 0` после `destroy` — например, в React,
где StrictMode запускает модуль, убирает и запускает снова (глава 08).

## Ошибки

> **Анимация срабатывает раньше/позже** — высота поменялась после расчёта. Кит пересчитывает
> сам, но если меняете высоту своим кодом без `ResizeObserver`-видимых изменений, вызовите
> `ScrollTrigger.refresh()`.
>
> **`position: fixed` внутри блока ведёт себя как `absolute`** — у предка остался
> `transform`. Используйте `clearProps`.
>
> **На телефоне всё прыгает при прокрутке** — у вас свой `gsap` без
> `ignoreMobileResize`. Импортируйте из `kit/js/core/gsap.js`.
>
> **Внутри модалки крутится страница** — свой блок с прокруткой без `overflow: auto` или без
> `data-lenis-prevent`.
>
> **Анимации есть даже у тех, кто просил меньше движения** — модуль не проверяет `ctx.reduced`.
